## 0. Решения по позиционированию (зафиксировать до презентации)

| Вопрос | Решение |
|--------|---------|
| Какой кейс фонда | **Кейс 2 «Управление здоровьем вне клиники»** (теги IoT, Health). Целевые роли кейса — человек с инвалидностью, родственник, соцработник, **врач** — точно совпадают с нашей моделью «пациент дома / врач видит аналитику удалённо». |
| Первичная целевая группа | **Дети с ДЦП (детский церебральный паралич)** — изначальная и основная аудитория проекта. ДЦП ~1.5–2.5 на 1000 новорождённых; нарушение функции руки у ~50–83%. Формы: спастическая (чаще всего), дискинетическая, атаксическая. Взрослые после инсульта/ЧМТ — возможные вторичные сегменты при масштабировании. |
| Что честно заявляем как «работающий AI» | Признаки движения (Слой 1) + персональный z-score к личной норме (Слой 2). Обученная модель — эксперимент на синтетике, в заголовок вердикта на демо не выносить. |
| Границы измерения (honest scope) | Устройство меряет **ориентацию запястья/предплечья** (roll/pitch): ROM, тремор, плавность. **НЕ меряет** хват и мелкую моторику пальцев. Заявлять как «мотивация + мониторинг крупной моторики руки», а не «восстановление кисти целиком». |

## 1. Критерии оценки ITMLab и наш разрыв

| Критерий | Вес | Текущая готовность | Главный разрыв |
|----------|-----|--------------------|----------------|
| Технологичность и MVP | 30% | Высокая | Зависимость от несертифицированного самодельного железа; модель на синтетике |
| Универсальный дизайн | 25% | Низкая–средняя | Web Bluetooth не работает на iPhone/Safari; одна ось; нет доступности интерфейса (контраст, экранный диктор, размер целей) |
| Применимость в Казахстане | 20% | Средняя | Нет привязки к статистике/маршруту реабилитации РК в материалах; нет локализации данных под закон РК |
| Проверка с пользователями | 15% | **Отсутствует** | Нет ни одного реального теста с пациентом или врачом; демо-данные синтетические |
| Этика и безопасность данных | 10% | Частичная | Нет согласия на обработку, нет дисклеймера «не диагноз», нет учёта 152-ФЗ-аналога РК (локализация ПДн) |

## 2. Backlog — продукт / код (приоритет: P0 критично, P1 важно, P2 желательно)

- [ ] **P0. Дисклеймер «не медицинское изделие / не диагноз».** Добавить видимую плашку в дашборд
      врача (`web/src/pages/PatientDetail.jsx`) и на экран результата пациента (`SessionResult.jsx`):
      аналитика носит вспомогательный характер, не заменяет осмотр врача. Закрывает критерий «Этика».
- [ ] **P0. Экран согласия на обработку данных** при регистрации/создании пациента
      (`web/src/pages/Register.jsx`, `PatientList.jsx` форма создания). Флаг согласия хранить в модели
      `Patient`/`User`. Без него питч уязвим по «Этика и безопасность» (10%).
- [ ] **P1. Доступность интерфейса (универсальный дизайн, 25%).** Прогнать дашборд и экраны игры
      по чек-листу WCAG AA: контраст текста, размер кликабельных целей ≥44px, фокус с клавиатуры,
      `aria-label` на иконочных кнопках. Это прямой вклад в самый «дорогой» после MVP критерий.
- [ ] **P1. Деградация без Web Bluetooth.** На iPhone/Safari Web Bluetooth недоступен. Добавить
      явное определение неподдерживаемого браузера и понятное сообщение + клавиатурный режим как
      заявленный fallback (он уже есть в `packages/ble`, но не отражён в UI как осознанный путь
      «без устройства»). Снимает удар по «универсальному дизайну».
- [ ] **P1. Режим «реальный пользовательский тест».** Подготовить сценарий, при котором можно
      посадить врача за демо-дашборд и пациента за игру (хоть на клавиатуре) и собрать обратную
      связь — закрывает критерий «Проверка с пользователями» (15%). Технически: убедиться, что
      `DEMO_MODE` + клавиатурный fallback дают связный сквозной сценарий без железа.
- [ ] **P2. Вторая ось / расширение под сегменты.** Для постинсультных и ДЦП-сценариев продумать,
      нужна ли игра на pitch (сгибание/разгибание) — инфраструктура `GAME_AXIS`/`SECONDARY_AXES`
      готова (`api/app/ml/games.py`). Не блокер 1-го этапа, но усиливает «технологичность».
- [ ] **P2. Локализация хранения данных под РК.** Проверить, где предполагается хостинг Mongo;
      для медицинских ПДн граждан РК нужна локализация на территории РК. Зафиксировать как пункт
      архитектуры в `docs/TECHNICAL.md` §6.

## 3. Backlog — материалы / исследование (для слайдов и речи)

- [ ] **P0. Цифры проблемы (РК).** Вставить в слайд 1: >40 000 инсультов/год в РК, ~60% →
      инвалидность, ~70% нуждаются в посторонней помощи, только ~10% возвращаются к обычной жизни;
      >200 тыс. получателей пособия по инвалидности. (Источники — см. §5 этого файла.)
- [ ] **P0. Доказательство, что реабилитация работает.** Слайд 2/3: опереться на опубликованные
      RCT по exergame/IMU-реабилитации (ДЦП, инсульт, Паркинсон, РС). Эффект — через нейропластичность:
      интенсивная, повторяющаяся, целенаправленная практика; геймификация поднимает приверженность.
- [ ] **P1. Конкурентный ландшафт.** Подготовить 1 слайд/абзац: Neofect Rapael, MindMaze, Nintendo
      Wii/Leap Motion-подходы. Наше отличие: дешёвое железо (ESP32-C3), локальное решение для РК,
      серверная ML-аналитика для врача, открытость к региональной телереабилитации.
- [ ] **P1. Бизнес-модель.** Сформулировать: кто платит (реабилитационные центры/клиники как B2B,
      либо включение в гос. программу медико-социальной реабилитации), цена железа, SaaS-подписка
      на дашборд врача, unit-экономика. Сейчас в проекте НЕ определена.
- [ ] **P1. TAM/SAM/SOM.** Оценить рынок: РК (инсульт+ДЦП+ЧМТ), затем СНГ. Привязать к §5 цифрам.
- [ ] **P2. Интервью.** Поговорить хотя бы с 1 реабилитологом и 1 пациентом/родителем; вставить
      1 цитату в слайд 1 как «проверка разговором» (прямо требуется кейсом 11 и критерием 15%).

## 4. Что у нас уже сильное (использовать как опору, не переделывать)

- Сквозной рабочий прототип: BLE → игра → признаки → ML → дашборд врача (критерий MVP 30%).
- Честная архитектура ML с разделением «надёжное (z-score) / экспериментальное (модель)».
- Демо-режим с детерминированными профилями (норма, постинсультная асимметрия, тремор Паркинсона).
- Гард валидности сессий (отсев «пустых прогонов») — зрелая инженерная деталь.
- Сырой ряд движения сохраняется — задел под обучение моделей и будущую клин. валидацию.

## 5. Источники (для цитирования в презентации)

Статистика РК:
- Инсульт в РК (>40 тыс./год, ~60% инвалидизация, ~10% возврат к жизни): inform.kz.
- Получатели пособий по инвалидности РК: stat.gov.kz, inva.gov.kz.

Клинические доказательства (exergame / IMU-реабилитация):
- ДЦП, RCT video games vs нейроразвивающая терапия (превосходство по мануальной ловкости): PubMed 32524538.
- ДЦП, IMU-игра Rapael Kids (клин. исследование): NCT02949817.
- ДЦП, домашняя VR + носимые IMU, RCT 40 детей: Frontiers Pediatrics 2023.
- Нейропластичность ДЦП (интенсивная повторяющаяся практика, HABIT-ILE): PMC12554712.
- Инсульт, exergame для верхней конечности: Frontiers Neurology 2024 (PMC10883060).
- Приверженность домашней реабилитации (низкая без сопровождения): PMC9706874, PMC7757643.
- Паркинсон / РС / ЧМТ — exergame обзоры: npj Digital Medicine 2025, Frontiers Neurology 2021.
- Распространённость: инсульт — нарушение руки у 55–80% выживших; ДЦП ~1/1000, поражение руки 83%.

## 6. Порядок работ (рекомендация)

1. Зафиксировать позиционирование (§0) — это меняет все слайды.
2. Закрыть P0 по продукту (дисклеймер, согласие) и по материалам (цифры, доказательство эффекта).
3. Собрать недостающие материалы (конкуренты, бизнес-модель, рынок).
4. Только после этого — верстать 4 слайда и писать речь (≤1.5 мин).

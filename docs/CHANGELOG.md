## Готовность к ML-тесту, часть 1: разметка врача + панель сбора данных (2026-07-14)

  сбора был виден только через консольный `inspect_sessions.py`.

  Всего 28 api + 10 паритет зелёные.

## Аудит безопасности и качества данных: подготовка к сбору реальных пациентов (2026-07-11)

> Цель: чтобы сессии реальных детей сохранялись как ЦЕННЫЕ размеченные данные для ML,
> а не как несвязанный/загрязнённый поток; плюс закрытие найденных дыр безопасности.

**Качество ML-данных (главное):**
- **`input_source` у сессии** (`ble|keyboard|mixed|none`) — раньше клавиатурные сессии с
  СИНТЕЗИРОВАННЫМ рядом углов (game-2d `_updateCatcher` строит виртуальный roll из позиции
  платформы) были неотличимы от датчика и отравляли датасет. Теперь: web считает источник
  по событиям BleService (`resetInputStats`/`getInputSource` в `bleStore.js`), сервер
  сохраняет и НЕ пускает не-датчик в baseline (`routes/sessions.py`, `calibration.py`),
  рейтинг и выгрузку датасета. UI честно помечает такие сессии («тренировочный прогон»)
  и не собирает по ним метки боли/усталости.
- **Калибровка с клавиатуры больше не перезаписывает baseline** — раньше пробный прогон
  без датчика становился «точкой отсчёта» и весь прогресс считался от синтетики.
  На странице калибровки — предупреждение и честный экран результата.
- **`GET /admin/export/ml-dataset`** — готовая выгрузка обучающего датасета: сессии
  реальных пациентов (тестовые/демо/клавиатурные исключены), признаки + метки
  (боль/усталость/оценка врача) + контекст (диагноз, возраст, пол), личность
  псевдонимизирована стабильным `patient_key` (sha256 от patient_id).
- **nginx `client_max_body_size 16m`** для `/api/` — дефолтный 1 МБ ронял сохранение
  длинных сессий (25 Гц × ~15 мин > 1 МБ → 413, данные пациента терялись).
- Потолок `MAX_IMU_SAMPLES=200000` на ряд (защита RAM контейнера от мусорных клиентов).

**Безопасность:**
- **Утечка ИИН в рейтинге закрыта**: `/leaderboard` отдавал `username` = ИИН ребёнка всем
  вошедшим. Теперь `display_name`: своё имя (+`is_me`), врач — имена только своих,
  остальные — псевдоним «Игрок ····XXXX»; тестовые пациенты исключены из рейтинга.
- **Rate-limit на вход** (`auth/ratelimit.py`, в памяти, без зависимостей): 8 неудач на
  логин / 30 на IP за 15 минут → 429. Критично: логин = ИИН (предсказуем), пароль
  ребёнка — 6-значный ПИН.
- **`platform_access` теперь работает**: флаг проверяется в `get_current_user` (раньше
  админский тумблер «заблокировать» ничего не делал). Админ не может заблокировать/
  понизить сам себя.
- `/ml/features` и `/ml/predict` — только с авторизацией (были публичным вычислительным
  DoS-вектором для VPS 1 ГБ).
- Невалидный ObjectId в URL → 404 вместо 500 (sessions/patients/admin).

**Целостность данных и UX:**
- `DELETE /admin/users/{id}`: тестовый → каскад (карта+сессии+очки), реальный → удаляется
  только вход, медданные и ML-ряды остаются (карточка отвязывается).
- Очки в рейтинг не пишутся за калибровку и клавиатурные сессии (нечестное сравнение).
- Фронт: 401 по протухшему токену → авто-выход и редирект на /login (раньше — «залогинен»
  с ошибками на каждой странице).

  убивает наши контейнеры, а не соседний проект; mongo/api наружу не публикуются,
  только nginx (`WEB_PORT`, по умолчанию 8080), `/api` проксируется same-origin.

- **Healthcheck'и переделаны (dev + prod)**: mongo — TCP-проверка через bash вместо
  mongosh (тот поднимал Node-процесс ~140 МБ на каждый пинг — его и убивал OOM);
  api — python urllib вместо curl (curl в python:slim нет, проверка всегда падала).

## ML — 2-осевой анализ аномалий (roll + pitch) для City Driver (2026-06-18)

## ML — фикс train/serve skew: запись IMU-ряда 25 Гц + несглаженный угол (2026-06-18)

### Проблема
Модель аномалий обучена на синтетике **25 Гц** (`fs_hz=25`), где два самых важных признака —
спектральные `tremorPower` (~0.21) и `tremorFreqHz` (~0.18). Но игры писали ряд на **5 Гц**
(аккумулятор 200 мс) и притом **дважды сглаженный** (EMA в BLE → второй EMA в движке). При
5 Гц Nyquist = 2.5 Гц < нижней границы полосы тремора 3 Гц → `_spectral_tremor` структурно
возвращает `(0, 0)`, а EMA-сглаживание гасит тремор 4–8 Гц ещё до записи. Итог: ~40% «важности»
модели в продакшене мертвы — детектор тремора не мог сработать ни на одной реальной сессии.

### Сделано (только захват данных — модель НЕ переобучалась)
- `packages/ble/index.js`: событие `data` теперь несёт `calib` (калиброванный, но **несглаженный**
  угол) рядом со `smooth` (управление) и `raw` (диагностика). Аддитивно; UUID/команды/прошивка
  не изменены.
- `packages/game-2d/index.js`, `packages/game-3d/index.js`: отдельный канал записи `_rec*`
  (несглаженный) пишется в `imu_time_series` вместо `_smooth*`; частота записи 5 → **25 Гц**
  (`IMU_RECORD_MS=40`, Nyquist 12.5 Гц покрывает полосу тремора). Без устройства (клавиатура/демо)
  пишется синтез-угол как раньше (тремора там нет). `updateInput()` принял 4-й арг `rec`.
- `web/src/pages/Game2D.jsx`, `Game3D.jsx` и оба `demo.html`: прокинут `e.detail.calib` в запись.

### Проверка
- Доказательство на тремор-сигнале (медленное движение 0.4 Гц + тремор 6 Гц) через
  `extract_features`: **5 Гц** → `tremorFreqHz=0, tremorPower=0, tremorIndex=0`; **25 Гц** →
  `tremorFreqHz=6.0` (частота определена точно), `tremorPower=0.694`, `tremorIndex=0.773`.
- `pytest ml-service/tests/` → 10 passed (паритет `features.py` не затронут). `npm run build` зелёный.
- Осталось: подтверждение на железе ESP32 (нейтральная поза R/P/Y ≈ 0, тремор виден в признаках).
  Размер ряда вырос ×5 (60 с ≈ 1500 семплов) — приемлемо для Mongo.

### Решение (бэкенд, без удаления сырых данных)
- `api/app/ml/validity.py` (новый) — слой поверх вектора признаков (не трогает `features.py`,

- Демо-вердикты не затронуты: «Критично» там — реальная сессия (ROM=12, боль), не пустой прогон.
- Доки: `docs/TECHNICAL.md` §3 (Sessions + insights), §5 (валидность сессии).

## v7.1 — Исправление вырождения признаков smoothnessIndex / tremorIndex (2026-06-05)

### Критический баг

`smoothnessIndex = 0.0` и `tremorIndex = 1.0` для ВСЕХ сессий при частоте дискретизации ≥ 20 Гц.

**Причина:** формулы были откалиброваны под 5 Гц. При 25 Гц шум датчика усиливается в ~(25/5)² = 25× через трёхуровневое дифференцирование.

### Исправления (паритет JS ↔ Python сохранён)

1. **MA(3) сглаживание** перед дифференцированием — снижает шум в ~5× в jerk.
2. **dt-нормализация jerkScale** — `jerkScale *= max(1, (200/dt_avg_ms)²)`.
3. **Новый tremorIndex** — смены направления скорости с адаптивным порогом, оба соседних сэмпла должны превышать порог.

### Результат

| Признак | До (норма/аномалия) | После (норма/аномалия) |
|---------|---------------------|------------------------|
| smoothnessIndex | 0.000 / 0.000 | **0.848 / 0.800** |
| tremorIndex | 1.000 / 1.000 | **0.048 / 0.499** |

### Модель → v4-2026-06-05
- ROC-AUC test: **0.990**, CV: **0.991 ± 0.003**
- tremorIndex importance: 0.000 → **0.130**
- smoothnessIndex importance: 0.000 → **0.033**

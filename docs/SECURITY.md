# Безопасность и приватность — Axis

> Базовый контур безопасности и защиты данных. Axis обрабатывает **медицинские данные детей**
> (ИИН, диагноз, движения), поэтому планка выше обычного веб-приложения.
> Статусы честные: `Готово` · `Частично` · `Планируется`. Не выдавать планируемое за готовое.
>
> Связанные документы: `docs/RISK_REGISTER.md` (риски и владельцы), `docs/TECHNICAL.md` (архитектура),
> `docs/DEPLOY.md` (боевое развёртывание). Последнее обновление: 2026-07-13.

---

## 1. Что мы защищаем — классификация данных

| Класс | Примеры | Правила обращения |
|-------|---------|-------------------|
| **Чувствительные ПДн / медданные** | ИИН ребёнка, диагноз (форма ДЦП), возраст, пол, сырой ряд движений | Минимизировать; не отдавать наружу без необходимости; псевдонимизировать в выгрузках; не логировать |
| **Учётные** | Пароли/ПИН (хеши), JWT-токены | Только хеш (никогда plaintext); секрет JWT — из окружения; токены не логировать |
| **Операционные** | Метрики сессий, счёт, агрегаты | Внутри системы; в лидерборде — без раскрытия личности |
| **Публичные** | Версия API, статус здоровья | Свободно (`/api/health`) |

Принцип: **минимизация данных** — не собираем и не отдаём то, без чего можно обойтись.

## 2. Текущие меры (контроль)

### Аутентификация и авторизация
- **JWT (HS256)**, срок из `JWT_EXPIRE_DAYS`. Секрет — из окружения (`JWT_SECRET`). — Готово
- **Fail-fast боевой конфигурации**: при `APP_ENV=prod` приложение НЕ стартует с дефолтным/коротким
  `JWT_SECRET` или включённым `DEMO_MODE` (`api/app/config.py`, `main.py`). — Готово
- **IDOR-гард** (`verify_patient_access`): врач видит только своих пациентов. Сохранять на всех новых
  роутах с `patient_id`. — Готово
- **Rate-limit входа** (`api/app/auth/ratelimit.py`): против брутфорса ИИН+ПИН. — Частично
  (проверить покрытие всех точек логина; учесть работу за обратным прокси — реальный IP из заголовка).

### Транспорт и границы
- **HTTPS для BLE** (Web Bluetooth требует secure context): Caddy/Cloudflare Tunnel. — Готово
- **CORS allowlist** (`ALLOWED_ORIGINS`), не `*`. — Готово
- **Лимит тела запроса** nginx `client_max_body_size 16m` + `MAX_IMU_SAMPLES` — защита от мусорных/
  раздутых полезных нагрузок. — Готово

### Данные и выгрузки
- **Псевдонимизация в ML-выгрузке** (`/admin/export/ml-dataset`): стабильный `patient_key`
  (sha256 от `patient_id`), без прямых идентификаторов. — Готово
- **`input_source`**: датчик vs клавиатура — не пускаем не-датчик в baseline/выгрузку. — Готово

## 3. Контур приватности детских медданных (до пилота в клинике)

Это условие выхода за пределы теста. Пока не закрыто — работаем только на тестовых/своих данных.

| Требование | Что нужно | Статус |
|-----------|-----------|--------|
| **Информированное согласие родителя/опекуна** | Явный экран согласия при регистрации ребёнка; хранить факт, версию и дату согласия | Планируется |
| **Политика хранения и удаления** | Сроки хранения; право на удаление данных ребёнка; процедура удаления (не только soft) | Планируется |
| **Шифрование at-rest** | Шифрование тома/базы MongoDB на сервере; секреты — вне репозитория | Планируется |
| **Аудит доступа врача** | Лог «кто-когда-к-какому пациенту обращался»; неизменяемость; хранение | Планируется |
| **Минимизация и псевдонимизация** | Хранить ИИН только где юридически нужно; отделить идентификацию от аналитики | Частично |
| **Согласие на обработку для ML** | Отдельно фиксировать разрешение использовать данные для обучения модели | Планируется |

## 6. Принципы (не нарушать)

- Метрики и вердикты — **только на сервере**, не на клиенте.
- Никаких ПДн (ИИН, диагноз) **в URL/query, в логах, во внешних сервисах** без явной необходимости.
- **Не ослаблять** дисклеймеры «не диагноз» и не усиливать ML-заявления сверх обоснованных.
- Секреты — **только из окружения**; дефолтные значения не годятся для прода (проверяется fail-fast).

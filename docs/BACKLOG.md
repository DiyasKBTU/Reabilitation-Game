## 1. Клиническая валидность и регуляторика (бизнес-критично)

- 🔴 **Нет клинической валидации.** Все ML-вердикты (`anomaly`, `pattern`) обучены на синтетике /
  здоровых взрослых (`validation=none`). Медицинские заявления делать НЕЛЬЗЯ. Блокер для вывода
  как мед-продукт. → Нужен доступ к пациентам ДЦП + этический комитет; мост сбора данных готов
  (`mongo_loader`), не хватает размеченных реальных сессий.
- 🔴 **Регуляторный статус не определён.** «Аналитика боли/усталости» может попадать под
  медицинское изделие (зависит от юрисдикции, в РК/РФ/ЕС разные правила). До сертификации
  позиционировать строго как **тренажёр + поддержка решения**, не диагностику.
- 🟡 **Риск over-trust врачом.** Плашки «не диагноз» есть, но если их убрать/проигнорировать —
  паттерн/аномалия выглядят авторитетно. → не усиливать формулировки, держать дисклеймеры.

## 2. Безопасность и приватность (детские медданные)

- 🔴 **Нет rate-limiting / локаута на логин.** Вход пациента = ИИН (12 цифр) + ПИН (6 цифр).
  Без ограничения попыток ПИН перебирается за ≤10⁶ запросов. → лимит попыток на IP/учётку +
  экспоненциальная задержка / временный локаут. (`api/app/routes/auth.py`).
- 🟡 **JWT_SECRET по дефолту только предупреждается, не запрещается.** В проде с дефолтом токены
  подделываемы. → fail-fast (отказ старта) при дефолтном секрете в prod-режиме (`main.py`/`config`).
- 🟡 **Приватность не формализована.** Хранятся диагноз, ИИН, движения ребёнка. Нет: шифрования
  at-rest, политики хранения/удаления, явного согласия родителя, аудит-лога доступа врача. →
  обязательно перед пилотом в клинике.
- 🟢 IDOR-гард есть (`verify_patient_access`) — хорошо, сохранить при новых роутах.

## 3. ML — слабости

- 🟡 **Паттерн по ОДНОЙ сессии.** Шумная сессия может «перекинуть» класс. → сглаживание по N
  последним сессиям (мода/среднее вероятностей) и/или показ тренда паттерна, а не точечного.
- 🟡 **Путаница spastic↔asymmetric** (по 6 в confusion matrix). → при низкой уверенности
  объединять в «смешанный/неопределённый» вместо уверенного неверного класса.
- 🟡 **Системный риск синтетики:** модель учит генератор, не реальность. Митигировать накоплением
  реальных размеченных сессий (инфраструктура готова) + честные дисклеймеры (есть).
- 🟢 Честность маркирована (`validation=none`, дисклеймеры, `validate_baseline.py`) — хорошо.

## 4. UX / продукт

- 🟡 **Источник «у каждой цифры» — частично.** Сделано на уровне сессии (строка «Качество данных»)
  + per-metric «—» для неизмеренного. Нет per-number tooltip с нормой/обоснованием. → тултипы.
- 🟡 **Зависимость от устройства.** ESP32 в доработке, прошивка НЕ пишет сырой ряд (Firebase =
  только агрегаты) → полные 14 признаков только с будущего устройства. Риск «демо ≠ реальность».
- 🟡 **Нет врачебных пресетов сложности** под уровень MACS. Персональный диапазон есть, но настройка
  игры под тяжесть ДЦП — вручную. → пресеты лёгкий/средний/сложный по MACS.
- 🟡 **Веб-отображение вторичной оси / реакции** проверить на полноту (City Driver multi-axis,
  reactionMs/avoidanceRate). 
- 🟢 Idle-фильтр, honest-плашки, строка качества, карточка паттерна — хорошо.

## 5. Технические / инфраструктура

- 🟡 **Модель-артефакты в git** (anomaly 6.9 МБ + pattern 5.3 МБ бинарники). Репо растёт при
  каждом переобучении. → git-LFS или выкладка моделей отдельно (CI/registry).
- 🟡 **Нет CI.** Тесты (pytest 20+10, vitest 4, build) гоняются вручную. → GitHub Actions на PR:
  api-тесты + паритет + фронт-тесты + сборка.
- 🟡 **Дубль `FEATURE_KEYS`** в `train.py` и `anomaly.py` (разные пакеты). Терпимо (артефакт несёт
  свои ключи), но риск рассинхрона при правке. Аналогично `pattern` vector в train_pattern/pattern.py.
- 🟡 **Тихая деградация ML.** Ошибки инференса гасятся в `None`/rule-режим без сигнала. → лог/метрика
  «как часто упали в fallback».
- 🟢 Чисто от TODO/FIXME-долга; тесты зелёные; паритет под защитой golden-теста.
- 🟢 **Доконсолидировать доки:** `ML_SPEC.md` помечен историческим, но ещё жив из-за 8 ссылок в коде
  (§5 Firebase-находка, §3.4 LLM-принцип, §6). Полностью вывести = перенести §5 в `TECHNICAL.md §4`
  и перенаправить 8 комментариев → тогда удалить файл. Сейчас отложено (правка рабочих комментариев).

- Партнёрство с клиникой ДЦП = одновременно **реальные данные + клиническая валидация** (закрывает 🔴 §1).

## 2. Игры — детальный разбор

**Сильные стороны (проверено в коде):**
- **Delta-time физика** — скорость не зависит от FPS; плотность IMU-сэмплов не зависит от железа пациента.
- **Запись IMU по реальному времени ~5 Гц** (`_updateIMURecord`) — корректные временные ряды.
- **Чистая архитектура**: движок-класс, `canvas` + колбэки, ноль DOM/fetch/localStorage внутри → переиспользуемо и тестируемо (`demo.html`).
- **game-3d**: object pooling (нет аллокаций в кадре), `dispose()` GPU-ресурсов, HiDPI; **game-2d**: backing-store под devicePixelRatio.
- **Клиническая привязка**: «зональные» цели у краёв экрана требуют полной амплитуды кисти → игра напрямую тренирует ROM.

**Дефекты:**
1. **game-2d не синтезирует roll для клавиатуры** → без устройства IMU-ряд пустой, признаки `valid:false`.
   **Для демо без ESP32 показывать City Driver (game-3d)** — он синтезирует roll и даёт валидные ML-данные.
2. Очки поощряют скорость (комбо) — для пациента с болью конфликт с терапией; частично смягчено (`emphasizeQualityOverScore`).

## 3. ML/AI — три слоя разного качества

**Слой 1 — Признаки (`features.py`). Реально, защищаемо.**
12 признаков: ROM, peak/mean velocity, jerk→smoothness, tremorIndex, symmetryIndex, pauseRatio, repetitions, activeTime.
Обоснование: MA(3)-сглаживание перед дифференцированием, dt-нормализация jerk, адаптивный порог тремора.
Литература: Krakauer 2006, Gladstone 2002, Shumway-Cook 2007.

Дискриминация (среднее по 60 сессиям/профиль, `analyze_pitch.py`):

| profile | rom | peakVel | smooth | tremor | pause | active |
|---|---|---|---|---|---|---|
| normal | 54.8 | 134.5 | 0.87 | 0.02 | 0.07 | 21.3 |
| pain | 19.8 | 88.9 | 0.82 | 0.07 | 0.33 | 5.5 |
| tremor | 49.0 | 213.3 | 0.76 | 0.51 | 0.11 | 13.8 |
| asymmetry | 37.6 | 137.0 | 0.81 | 0.16 | 0.15 | 13.1 |

**Слой 2 — Персональный z-score baseline (`anomaly.py`, rule-режим). Реально, самое защищаемое.**
Сравнивает сессию с личной нормой (≥3 прошлых сессий), объясняет «что и на сколько σ отклонилось».
Не требует обучающих данных → работает с первого пациента. **В питче вести именно это как AI.**

**Слой 3 — Обученная модель (IsolationForest + RandomForest). Заглушка.**
- Обучена на **100% синтетике** (`source = "Синтетика v2 (600 окон)"`).
- **ROC-AUC 0.99 вводит в заблуждение**: «аномалии» порождены теми же параметрами (низкий ROM, паузы, тремор), которые потом измеряют признаки → модель угадывает генератор (near-circular).
- Клинической валидации нет.

Поведение модели по профилям (in-distribution, `analyze_pitch.py`):

| profile | normal% | attention% | critical% |
|---|---|---|---|
| normal | 100 | 0 | 0 |
| borderline | 93 | 7 | 0 |
| fatigue | 17 | 28 | 55 |
| pain | 0 | 0 | 100 |
| tremor | 0 | 0 | 100 |
| asymmetry | 7 | 10 | 83 |

Чистое разделение, ноль ложных срабатываний на норме — но это «модель выучила синтетику»,
а не «находит боль у людей». Честная формулировка обязательна.

## 5. Диаграммы

**Поток данных:**
```
[Пациент: кисть] → ESP32-C3+IMU →BLE→ packages/ble → игровой движок (запись IMU 5 Гц)
   → web/(React) →POST /api/sessions→ api/(FastAPI) → extract_features() [Слой1]
   → MongoDB (features + СЫРОЙ imu_time_series = data moat)
GET /api/insights → detect_anomalies() [Слой2 z-score] + model.joblib [Слой3 заглушка]
   + build_recommendations() → Дашборд врача
```

**Data flywheel (стратегическая диаграмма):**
```
Пациент играет → IMU-ряды + результат → features → SessionResult собирает МЕТКУ
(боль 0–2, усталость 1–10) → [накопление реального размеченного датасета]
→ переобучение модели v_n → лучше рекомендации → выше доверие врача → больше использования ↺
```
**Ключевой инсайт:** приложение уже собирает ground-truth метки (`SessionResult.jsx`) и
сохраняет сырые ряды. Петля «метки → переобучение» пока разомкнута — замкнуть её и есть AI-roadmap.
Дополнительно: у проекта есть **реальные данные с устройства в Firebase** (координаты) —
источник, который закрывает дыру «обучено только на синтетике» (см. ML_SPEC.md §5).

## 6. Материалы для питч-дека

### Проблема
Домашняя реабилитация проваливается: приверженность падает с **63–82% в стационаре до ~47%
после выписки**; ключевые барьеры — **отсутствие мотивации и усталость**. Врач не видит,
что происходит дома: нет объективных данных, решения «на глаз» на редких приёмах.

### Решение
Дешёвый IMU на кисть + браузерные игры → упражнения становятся мотивирующей игрой, а движение —
**объективными клиническими метриками** (амплитуда, плавность, тремор, асимметрия). Врач получает
удалённый дашборд с трендами, персональным детектором отклонений и рекомендациями.

### Рынок (со ссылками)
- Телереабилитация: **$5.32 млрд (2024) → $11.81 млрд (2030), CAGR 13.2%**.
- Виртуальная реабилитация: **$630 млн (2024) → $2.3 млрд (2030), CAGR 24.4%** (быстрейший сегмент).
- Нейрореабилитационные устройства: **~$2.4–2.66 млрд (2025)**, носимый сегмент CAGR ~13.9%.
- TAM — телереабилитация; SAM — домашняя нейро/кисть-реабилитация с датчиком+софтом в целевой гео;
  SOM (снизу вверх) — `клиники × пациентов/клинику × цена подписки`. Числа SAM/SOM зависят от гео и модели (B2B/B2C/B2B2C).

### Конкуренты
| Игрок | Подход | Деньги/статус | Где мы сильнее |
|---|---|---|---|
| Neofect RAPAEL | Сенсорная перчатка + игры + AI (кисть/нейро) | Серийный продукт с 2010 | Дешёвый generic-IMU vs проприетарная перчатка; браузер без установки |
| SWORD Health | Computer-vision MSK + клиницисты | **$4 млрд оценка**, купил Kaia за $285 млн (2026) | Другой сегмент (MSK); мы — точные углы кисти через IMU |
| Kaia Health | CV без железа, MSK+COPD | $123 млн, поглощён | То же |
| MindMaze | Нейро-VR | Крупный нейро-игрок | Дешевле, web, без VR-шлема |
| Статус-кво | Очная ЛФК + бумажные памятки | — | Объективные данные + ежедневная мотивация дома |

### Дифференциация
1. Стоимость (ESP32-C3 + IMU ≪ проприетарных перчаток/камер).
2. Дистрибуция: web + Web Bluetooth, без установки приложения.
3. Объективность врачу: серверные, аудируемые метрики + персональный baseline.
4. Data-moat: сырые IMU + метки боли/усталости → петля переобучения.
5. Расширяемость: ось управления конфигурируема (`GAME_AXIS`), новые игры за дни.

### Требования
- Функциональные (**реализованы**): BLE-захват, ≥2 игры, признаки, детектор отклонений, рекомендации, ролевой доступ, рейтинг, метки самочувствия.
- Пробелы (NFR): клиническая валидация, сертификация мед.изделия, локализация данных (152-ФЗ/РК), iOS/Safari (Web Bluetooth не поддерживается), офлайн-режим, экспорт отчётов (PDF — добавлен).

### Roadmap
- **MVP (готово):** 2 игры, BLE, feature-engine, z-score-аналитика, рекомендации, дашборд, авторизация.
- **Q1 после раунда:** замкнуть flywheel + интеграция Firebase-данных + LLM-explainer + пилот 1–2 клиники.
- **Q2–Q3:** клиническая валидация, первая модель на реальных данных, путь к сертификации, решение по iOS.
- **Фаза 2:** временные DL-модели на сырых IMU, мультисенсорика, новые нозологии.

### Технологии
FastAPI + MongoDB (Beanie/Motor, JWT) · React + Vite + Tailwind + Zustand · framework-agnostic
игровые движки (Canvas2D / Three.js) · ML встроен в `api/app/ml`, тестируется изолированно
(`/api/ml/*`) · ESP32-C3 + IMU через Web Bluetooth · Docker-compose.

### Риски (показывать самим — повышает доверие)
ML без клинической валидации · DIY-железо без сертификации · Web Bluetooth не работает на iOS ·
регуляторика/локализация данных · зависимость от внешнего LLM (митигируется fallback’ом).
